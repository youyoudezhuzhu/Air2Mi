# 单音箱测试音

在妙播音箱列表点击“测试音”，选择 1–100% 的整数音量，再确认播放。点击“停止”结束；最长五分钟自动结束。所选设备音量在停止后保留，不更改接收器配置。

## 实际调用

Host 先读取真实 Engine 状态；存在选中接收器（包括暂停）、主源或活动输出时拒绝。再次核对空闲后停止主实例，用独立临时目录启动同一已安装签名内核。临时配置仅采用内核既有 file profile，创建指定单目标的 `POST /v1/sessions`。退出调用会话停止接口，停止临时实例、删除临时资源，再恢复原入口。原 Registry、身份和路由不迁移、不删除。

浏览器仅提交音箱 ID 与 volume_percent；拒绝文件路径、任意字段、非整数和越界音量。受控 WAV 为固定短旋律重复的 330 秒 PCM 资源，流式写入临时目录；不依赖内核中未生效的 file loop 标记。Host 未实现音频协议。临时 file profile 使用原有文件起播时基，不改变日常 AirPlay 低延迟参数。

## 生命周期

首个音频 ACK 确认目标后显示播放；连接失败如实报告。手动停止和五分钟 deadline 会取消在途 HTTP。临时实例未确认停止时保留忙状态并重试清理，禁止同时恢复主实例。测试期间禁止配置修改和更新。主实例重建会短暂刷新 AirPlay 入口，所以要求先取消全部投放；不把测试音混进当前音乐。

## 验证与限制

真实会话已在两种音箱上收到目标首帧确认，分别验证手动停止和旧短时限自动停止，检查只有目标输出、原注册表一致、临时目录删除、主入口恢复。新五分钟上限的计时/请求取消与资源长度已通过自动回归；五分钟完整实机运行被用户当前投放安全拒绝，尚未宣称完成长时间听音。没有用户声学确认，首帧 ACK 不等于声学验收。

测试音量停止后不会自动恢复旧值。现有 Engine 缺少独立安全的无播放音量恢复接口，不以复制协议或修改内核绕过。
